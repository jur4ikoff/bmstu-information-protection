# Документы на Typst

Механика вёрстки: синтаксис, метки, ссылки, фигуры, формулы, библиография, сборка. Навык не касается того, что писать - только того, как это оформить.

**Приоритет.** Настройки конкретного документа живут в его шаблоне (`show`- и `set`-правила, вспомогательные функции). Они главнее этого навыка везде, где расходятся. Здесь - общая рамка и типовые идиомы.

## Ориентация перед правкой

Прежде чем править `.typ`-файл, разберись в устройстве конкретного проекта. Шаблоны различаются: где-то нумерация фигур сквозная, где-то по разделам; где-то есть вспомогательные функции, где-то их нет; имена и расположение файлов свои.

1. Посмотри содержимое каталога с документом целиком.
2. Прочитай главный файл (тот, что собирает остальные через `#include`) - он показывает порядок частей и подключаемый шаблон.
3. Прочитай файл конфигурации шаблона - из него видно, какие `show`-правила действуют, какие пакеты подключены, как нумеруются заголовки, фигуры и формулы.
4. Найди вспомогательные функции (`#let ...`) - они могут быть определены как в шаблоне, так и прямо в разделе, где используются. Не вызывай функцию, пока не увидел её определения в этом проекте.
5. Посмотри соседний фрагмент того же файла - и повторяй уже сложившиеся идиомы, а не вводи свои.

## Типичная структура проекта

Ниже - распространённая раскладка, а не обязательный контракт. В конкретном проекте имена, нумерация и набор файлов могут отличаться; ориентируйся на то, что реально лежит в каталоге.

```
report.typ            # главный файл: подключает шаблон и собирает разделы через #include
00_title.typ          # титульный лист (часто вместо него подшивается готовый PDF)
01_abstract.typ       # реферат
02_intro.typ          # введение
03_analytical.typ     # содержательные разделы, по файлу на раздел
...
07_conclusion.typ     # заключение
08_references.yml     # библиография в формате Hayagriva (YAML)
09_appendix.typ       # приложения
template/             # оформление: config.typ, титульник, CSL-стиль, логотипы
images/               # растровые и векторные иллюстрации
Makefile              # сборка PDF и подготовка диаграмм
```

Главный файл выглядит примерно так:

```typst
#import "template/bmstu.typ": *
#show: config.bmstu_config

#include "01_abstract.typ"
#outline()
#include "02_intro.typ"
#include "03_analytical.typ"
#include "07_conclusion.typ"

#bibliography("08_references.yml")
#include "09_appendix.typ"
```

## Разметка и код

Typst различает режим разметки и режим кода. В разметке `#` переводит в код на одно выражение: `#figure(...)`, `#let x = 1`, `#sym.plus.minus`. Внутри кода разметка возвращается через квадратные скобки: `caption: [Текст подписи]`.

Отсюда типовая ошибка: `#` перед функцией нужен только в разметке. Внутри аргументов другой функции - уже режим кода, и лишний `#` там будет ошибкой.

## Типографика

Неразрывный пробел `~` - основной рабочий инструмент. Он ставится там, где перенос строки разорвал бы смысловую единицу:

- перед ссылкой, чтобы предлог не оторвался от номера: `приведён на~@fig:eegsignal[рисунке]`;
- между числом и единицей измерения: `500~Гц`, `64~канала`, `21~слайд`;
- перед тире в предложении: `Сигнал~--- последовательность отсчётов`;
- внутри составных обозначений: `с.~370`, `с.~2--3`.

Тире в видимом тексте документа пишется как `~---` (неразрывный пробел плюс три дефиса, Typst соберёт их в длинное тире). Обычный дефис в `.typ`-файле уместен только внутри комментариев `//` и в листингах кода. Диапазон чисел - два дефиса: `362--378`.

Кавычки набираются обычными двойными `"`: при `lang: "ru"` Typst сам подставит русские «ёлочки». Вводить символы `«»` вручную не нужно.

Не вставляй Unicode-символы напрямую. Используй встроенные средства: `#sym.plus.minus` вместо `±`, `#sym.times` вместо `×`, стрелки - в математическом режиме `$->$`, `$==>$`, `$<->$`.

## Заголовки

Нумерованные заголовки разделов - обычным синтаксисом, уровень задаётся числом знаков `=`:

```typst
= Аналитическая часть

== Анализ предметной области

=== Форматы хранения
```

Структурные элементы (РЕФЕРАТ, ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ) нумерации не имеют и центрируются:

```typst
#align(center, heading(numbering: none, [ВВЕДЕНИЕ]))
```

Заголовок «Вывод» в конце раздела не нумеруется и не попадает в содержание:

```typst
#heading(numbering: none, level: 2, outlined: false, [Вывод])
```

Структурные части обычно закрываются мягким разрывом страницы `#pagebreak(weak: true)` - «мягкий» означает, что подряд идущие разрывы схлопываются в один.

## Метки и ссылки

Метка ставится сразу за элементом, к которому относится, без пробела. У фигур, таблиц, листингов и формул она пишется **без префикса**:

```typst
#figure(
  image("images/eeg-signal.jpg", width: 90%),
  caption: [Пример многоканальной ЭЭГ-записи (31~канал)],
)<eegsignal>
```

Ссылка же пишется **с префиксом вида элемента**: `@fig:eegsignal`, `@tbl:entities`, `@eqt:barycentric`, `@lst:find-similar`.

**Заголовки - исключение.** Префикс `sec:` не синтезируется ничем, это ручное соглашение, поэтому у заголовков он входит в саму метку:

```typst
#align(center)[#heading[ПРИЛОЖЕНИЕ]<sec:appendix-materials>]
```

и ссылка повторяет её целиком: `@sec:appendix-materials[приложении]`.

**Важно.** Префиксы `fig:`, `tbl:`, `eqt:` и `lst:` даёт пакет `i-figured` - он подключается в шаблоне правилами `#show figure: i-figured.show-figure` и `#show math.equation: i-figured.show-equation` и заодно нумерует фигуры и формулы по разделам. Если в проекте пакет не подключён, этих префиксов нет и ссылка пишется просто `@eegsignal` (метки заголовков это не затрагивает). Проверь конфигурацию шаблона, прежде чем писать ссылку.

Квадратные скобки после ссылки задают supplement - слово, которое встанет перед номером. Туда кладётся русское слово в нужном падеже и числе:

```typst
приведён на~@fig:eegsignal[рисунке]        // "на рисунке 1.2"
показаны на~@fig:schemes[рисунках]         // "на рисунках 2.1"
сведены в~@tbl:entities[таблице]           // "в таблице 1.3"
вычисляется по~@eqt:edge[формуле]          // "по формуле 2.1"
рассчитываются по~@eqt:bary[формулам]      // "по формулам 2.2"
текст приведён в~@lst:find-similar[листинге]
подробности в~@sec:appendix-b[приложении]
```

Пустые скобки убирают слово и оставляют только номер - так удобно ссылаться внутри ячеек таблицы:

```typst
[Простой с фильтром], [Испытуемые от 60 лет], [@lst:q-simple[]],
```

## Фигуры

Любой нумерованный объект - рисунок, таблица, листинг - оформляется через `#figure` с подписью и меткой.

Рисунок:

```typst
#figure(
  image("images/electrodes-10-20.jpg", width: 100%),
  caption: [Расположение стандартных электродов системы 10-20 (A~--- вид сбоку; B~--- вид спереди)],
)<electrodes>
```

Таблица - `table` внутри `figure`, шапка выделяется через `table.header`, ширины колонок задаются списком (`1fr` тянется, `auto` по содержимому):

```typst
#figure(
  table(
    columns: (1fr, auto, auto, auto),
    align: (left, center, center, center),
    table.header([*Критерий*], [*EEGBase*], [*LORIS*], [*XNAT*]),
    [Сигналы в БД], [+], [--], [--],
    [Ролевая модель], [+], [+], [#sym.plus.minus],
  ),
  caption: [Сравнение существующих систем],
)<analogs>
```

Подпись таблицы шаблон обычно ставит сверху и выравнивает влево, подпись рисунка - снизу по центру. Вручную это не настраивается, за это отвечают `show`-правила шаблона.

Листинг - raw-блок внутри `figure`. Язык указывается после открывающих обратных кавычек, подсветкой заведует пакет `codly`:

```typst
#figure(
  ```sql
  SELECT * FROM subject WHERE age >= 60;
  ```,
  caption: [Запрос с простой фильтрацией],
)<q-simple>
```

Широкая фигура, не помещающаяся в поля, поворачивается на странице:

```typst
#rotate(
  -90deg,
  align(left)[
    #figure(
      image("images/eeg-study-bpmn.png", width: 90%),
      caption: [BPMN-диаграмма процесса проведения исследования],
    )<eegstudybpmn>
  ],
  reflow: true,
)
```

## Формулы

Выключная формула - доллары на отдельных строках, метка сразу после закрывающего доллара:

```typst
$
    f(A, B, P) = (B_x - A_x)(P_y - A_y) - (B_y - A_y)(P_x - A_x)
$<edge_function>
```

Строчная формула набирается в одну строку: `условию $w_0 + w_1 + w_2 = 1$`.

### Продолжение абзаца после формулы

Выключная формула разрывает текст на два абзаца, и Typst даёт второму из них красную строку. Формула же почти всегда стоит внутри предложения и абзаца не прерывает, поэтому продолжение набирается с нулевым отступом через `#par(first-line-indent: 0mm)[...]`:

```typst
близость двух упорядочений оценивается коэффициентом ранговой корреляции~@marapov2013:
$
  rho = 1 - (6 limits(sum)_(i=1)^n d_i^2) / (n (n^2 - 1)),
$
#par(first-line-indent: 0mm)[
  где $d_i$~--- разность рангов $i$-го фрагмента в двух упорядочениях, $n$~--- число фрагментов корпуса. Значение около единицы отвечает почти одинаковому порядку, около нуля~--- несвязанным порядкам.
]
```

Правило не зависит от того, что идёт за формулой - расшифровка переменных, продолжение рассуждения или и то и другое подряд. Красная строка появляется только там, где действительно начинается новый абзац. Обрати внимание и на пунктуацию: формула, встроенная в предложение, сохраняет знак препинания, который стоял бы на её месте в обычном тексте, поэтому перед словом «где» она закрывается запятой.

Та же надобность объясняет, зачем в проектах заводят вспомогательную функцию для блока пояснения - чтобы не выписывать настройку отступа у каждой формулы.

### Пояснение переменных

За формулой идёт блок пояснения переменных. Он открывается словом «где», абзацный отступ в нём снят, каждая переменная описывается отдельной строкой, строки разделяются точкой с запятой, последняя закрывается точкой:

```
где $A$, $B$~--- вершины ребра треугольника;
    $P$~--- проверяемая точка.
```

В проектах этот блок почти всегда обёрнут в локальную вспомогательную функцию, которая заодно снимает абзацный отступ. Имя у неё своё в каждом проекте (встречается, например, `list_for_equation`), и определена она может быть как в шаблоне, так и в начале того же файла раздела. Найди её определение прежде, чем вызывать; если функции нет - либо заведи свою рядом с первой формулой, либо оформи пояснение обычной разметкой.

Пример вызова такой функции:

```typst
#list_for_equation(elements: (
    [$A$, $B$~--- вершины ребра треугольника;],
    [$P$~--- проверяемая точка.],
))
```

## Списки

Нумерованный список - знак `+`, маркированный - знак `-`. Шаблон обычно переопределяет вид маркеров: первый уровень нумеруется как `1)`, вложенный - русскими буквами `а)`, `б)`, маркер списка отображается как тире.

```typst
Для достижения цели необходимо решить задачи:

+ провести анализ предметной области;
+ спроектировать базу данных;
+ реализовать приложение доступа.
```

## Библиография

Источники хранятся в YAML-файле формата Hayagriva. Ключ записи - идентификатор, по которому на неё ссылаются:

```yaml
ivanov2022:
  type: article
  title: "Устройство современного электроэнцефалографа"
  author: "Иванов А. А."
  parent:
    title: "Эпилепсия и пароксизмальные состояния"
    volume: 14
    issue: 4
  page-range: 362-378
  date: 2022
  language: ru

kemp2003:
  type: article
  title: "A simple format for exchange of digitized polygraphic recordings"
  author:
    - "Kemp B."
    - "Olivan J."
  url: "https://www.edfplus.info/specs/edfplus.html"
  date: 2003
```

Ссылка в тексте - `@ivanov2022`, с указанием страниц - `@ivanov2022[с.~370]` или `@ivanov2022[с.~2--3]`. Перед ссылкой ставится неразрывный пробел: `частота дискретизации от 500~Гц~@ivanov2022[с.~370]`.

Подключается библиография в главном файле: `#bibliography("08_references.yml")`. Стиль оформления задаётся в шаблоне - для ГОСТ это CSL-файл, лежащий рядом с шаблоном.

## Приложения

Приложения нумеруются русскими буквами и требуют отдельной настройки в своём файле: собственная схема нумерации заголовков, собственный `show`-правило заголовка и сброс счётчиков.

**Подводный камень.** Свой `show heading` в файле приложений превращает заголовок в `align(...)` раньше, чем сработает `i-figured.reset-counters` из общей конфигурации шаблона. Поэтому сброс счётчиков фигур, таблиц, листингов и формул нужно вызвать вручную внутри этого же `show`-правила - иначе нумерация внутри приложений пойдёт сквозной (Б.4 вместо Б.1).

```typst
#import "@preview/i-figured:0.2.4"
#import "template/config.typ": cyrillic-numbering, cyrillic-upper

#counter(heading).update(0)
#set heading(supplement: [Приложение], numbering: (..nums) => {
  let n = nums.pos()
  if n.len() == 0 { return "" }
  cyrillic-upper.at(n.first() - 1)
})

#show heading: it => {
  i-figured.reset-counters(it, return-orig-heading: false)
  align(center, [
    #let number = numbering(it.numbering, ..counter(heading).at(it.location()))
    #set text(size: 16pt, hyphenate: false)
    #v(1.5em, weak: true)
    #it.body~#number
    #v(1.5em, weak: true)
  ])
}

#show figure: i-figured.show-figure.with(numbering: cyrillic-numbering)
#show math.equation: i-figured.show-equation.with(numbering: cyrillic-numbering)
```

## Сборка

Если в каталоге есть `Makefile`, собирай через него - там уже прописаны нужные флаги и подготовка диаграмм.

Прямой вызов компилятора:

```bash
typst compile --no-pdf-tags --root .. report.typ
```

Имя выходного файла по умолчанию повторяет имя входного: рядом появится `report.pdf`. Явное имя вторым аргументом указывается только тогда, когда этого требуют правила проекта - например, когда работу нужно сдать под именем вида `ИУ7-61Б-Фамилия-Имя-КуР-РПЗ.pdf`; такое имя обычно уже прописано в `Makefile`.

Флаг `--root` обязателен, когда документ обращается к файлам выше своего каталога (изображения, диаграммы, общий шаблон). Без него компиляция упадёт на первом же таком пути. Флаг `--no-pdf-tags` отключает теги доступности - они мешают части внешних проверяющих программ читать PDF.

Для непрерывной пересборки при правках - `typst watch` с теми же флагами.

## Частые ошибки

1. **Метка фигуры с префиксом.** `<fig:name>` - неверно, метка фигуры, таблицы, листинга и формулы пишется голой: `<name>`, префикс появляется только в ссылке. У заголовков наоборот: `<sec:name>` вместе с префиксом.
2. **Ссылка без префикса при подключённом `i-figured`.** `@name` не разрешится, нужно `@fig:name`. И наоборот: если пакета нет - префикс у фигур лишний.
3. **Метка после промежуточного текста.** Метка привязывается к непосредственно предшествующему элементу, и пробелы, переводы строк и даже пустая строка между фигурой и меткой привязку не ломают - это вопрос опрятности кода, метку принято ставить вплотную. А вот если между фигурой и меткой вклинился абзац, метка привяжется к нему, и ссылка упадёт с ошибкой `cannot reference text`.
4. **Обычный пробел перед ссылкой.** Номер оторвётся от предлога при переносе строки. Нужен `~`.
5. **Длинное тире символом.** В видимом тексте пишется `~---`, а не `—`.
6. **Лишний `#` внутри аргументов функции.** Там уже режим кода.
7. **Сборка без `--root`.** Изображения за пределами каталога не найдутся.
8. **Ссылка на несуществующую метку.** Typst сообщит об этом только при компиляции - собирай документ после правок.
